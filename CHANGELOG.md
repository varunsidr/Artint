# Changelog

Changes under **Unreleased** have not been included in a tagged release. Verification below records the local pre-push checkpoint; a source push does not imply a release or a passing hosted CI run.

## Unreleased

### Fixed

- Topic-map selections open the matching theme panel after the finer-subtopic panel-identity change. Expanders now track their open state, and actual map events update that state without reopening manually closed panels during source/window browsing. The original live topic acceptance assertion is retained, with regression coverage for map changes and manual state preservation.

### Added

- Finer topic discovery inside each parent theme: one bounded leaf-density refit reuses the original article vectors, retains parent membership and explicitly lists members without a subtopic. Source browsing filters by subtopic or remaining members without new inference; unassigned sources now open in the reader. Generic reporting words are excluded from keyword labels. Version-2 exports retain the version-1 embedding cache identity and older results remain readable. Candidate subtopics still require human usefulness review.

- Reusable `validate_container.py --topics` mode with an original marked installation fixture and loopback scripted embedding service. It builds the topic-enabled runtime, checks live discovery/export/map selection and cached reruns, then re-creates the app and verifies vector reuse. Both validation modes check preservation of pre-existing container/volume identities and removal of the owned disposable project. CI defines separate base/topics image jobs; no hosted pass is implied.

- Experimental **Analytics → Topic discovery** with explicitly selected whole-collection scope, article-level semantic density clustering, class TF-IDF terms, representative/source inspection, outliers and exact normalized-copy accounting. An interactive PCA map supports theme selection; clustering uses the full vector space. Adjacent 7/30/90-day shares retain dated/undated denominators. Long articles disclose spread-passage sampling and retain excerpts. Browser results survive failed requests, label stale source/scope state and export JSON.
- A separate endpoint/model/digest/recipe topic-vector cache commits only after a stable model observation, leaving normal retrieval and saved labels unchanged. Optional pinned dependencies, opt-in Docker build configuration, native original-synthetic demo tooling and a [competitor/recent-research record](docs/topic-discovery.md) accompany the feature. No automatic model downloads, chat labeling, event-match certification or real-world quality score is introduced.

- Before/after selected-model manifest observations for explicit new Research questions and passage searches, with bounded GET-only metadata reads, timestamps, digests and whitelisted model details. Changed/incomplete observations remain visible in results/briefs and full JSON survives saved research and backup/restore. Metadata failure preserves a successful answer; reuse/navigation/save/reopen makes no new observation. Stable inventories do not certify inference weights or reused embeddings, and tag-keyed cache behavior remains unchanged.

- Versioned chat-request metadata for new Ollama generations: canonical-JSON message/schema and per-attempt payload fingerprints, requested options, requested/reported model names and observed runtime, without additional HTTP calls or prompt copies. Full JSON exports, saved research and backup/restore retain it; legacy results remain readable. Model-weight identity is explicitly unverified, and request equality does not establish output reproducibility or claim support.

- A simpler offline evidence-review screen with five questions at a time, expected answers beside saved source excerpts, inline highlighted articles, explicit confirmations, pending follow-up notes, browser progress recovery and portable progress downloads. The existing detailed reviewer and human-review contract are retained; no real labels or quality scores are generated automatically.

- Explicit **Save research** and an offline **Saved research** view with paged question search, original cited/abstained/passage-search results, source-revision notices, duplicate protection and confirmed deletion. Source deletion purges linked results atomically with visible counts. Library backup v2 includes saved research/source mappings and accepts v1 imports; restore preserves original citations and resolves local-ID collisions/remaps. Bounded snapshots use a separate revision so saves do not invalidate question reuse but do invalidate prepared backups.

Full-scope SQL aggregates and linked cell filters share notebook/CSV membership; unavailable checks/labels and zero baselines stay explicit. Calendar-aware caching, theme/mobile/keyboard behavior and specialist mode are retained. No new inference or source-quality score is introduced.

Added cited Markdown briefs and complete JSON research downloads that reuse the current result without inference or storage writes.

### Changed

- Detach nested generation metadata from client state before returning article analyses and research answers, so later client-state changes cannot alter an earlier result's metadata.

- Updated the development priorities to complete human review and measure the existing research pipeline before retrieval changes, demonstrate a small same-story evidence/brief workflow, and defer BERTopic to an optional measured corpus-navigation experiment. README/roadmap review counts now reflect six revised approvals and 54 pending cases with story grouping unconfirmed. This is a documentation update; no topic-discovery feature or quality result is delivered.

- Research now starts with collection/search and article summaries, separates questions from per-article summaries, and places model setup below the task workspace. Questions and batch summaries require explicit sources; filter/page changes clear source consent, selected titles can be reviewed, and a single-article summary stays within the selected group. Quick review explains unrelated evaluation distractors and groups other-story copies without changing test scope or labels. Retrieval rankings/models are unchanged; documented user feedback is qualitative.

- Database schema 7 adds saved research/source links and a separate history revision after the existing consistent pre-upgrade backup. The runtime/install smoke includes original hand-authored saved evidence across restore/recreation. Functional dashboard AppTest steps consistently use the existing 20-second startup budget, addressing repeated cold-host three-second navigation timeouts without changing production timing or performance targets.

- Compose now has the stable project name `artint`, with its own network/library/PDF volumes and an optional `.env.example` for port 8502. Explicit project overrides retain disposable validation isolation. A separate local persistent Artint stack was started and checked; existing containers and native library data were preserved. Older Compose installs can retain their previous project name to keep reaching their existing volumes.

- New captures omit a recognized publisher-home/social/newsletter promotion template before article validation, PDF generation and research. Quoted or mixed editorial content and following article sections are preserved. Diagnostics record removal counts, and extraction evaluation fingerprints the cleanup dependency. Existing stored copies/PDFs and frozen evidence are retained.

- Retain the last completed research answer and its exports through failed requests, offline model discovery and changed/empty filters, with an original-scope label and explicit session-only clear action. New exports include original completion time and source-selection fingerprints; passage searches record their embedding model. International source links use IDNA hostnames, and near-full mixed GPU residency no longer rounds to 100%.

- New generation automatically selects 8K/16K context, reserves answer space, disables truncation/context shifting and retries a complete underestimated request at most once at 16K. Context metadata appears in new analyses, research answers and evaluator rows. Generation requires the oldest checked compatible Ollama runtime, 0.40.11. Existing saved analyses and fixed-16K evaluation snapshots are retained.
- Library and Research separate general filters from topic/tag choices derived from all matching sources. Incompatible selections clear when the context changes; missing labels remain explicit.
- Pagination uses compact Previous/page-jump/Next controls. Analytics text is larger; Library and Analytics previews remove Markdown/image destinations while preserving stored sources and PDFs.
- Research answer cards expose cited passages directly. Retrieval details report searched passages, embedding reuse/creation and elapsed time.
- Embedding-cache reads use bounded SQL batches. The search model stays loaded between embedding batches and requests unload after the final batch. An identical question can reuse the last session result, with an explicit fresh-result bypass.
- Refreshed the README analytics screenshot using the original 36-article synthetic demo.
